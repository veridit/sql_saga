## Goal
User DDL cannot drop an era's bounds check, boundary check or sync trigger; only drop_era removes them.

## Purpose
These objects keep empty ranges and from >= until out of the table. Dropping one silently lets bad rows in until someone runs check_integrity.

## Principle
Refuse in the drop-protection event trigger with a message naming the era and the sql_saga call to use, as for era columns and the range type. Do not repair after the fact.

## Details
Found while documenting test 094 (hug 7yz6xb). s9 has been marked '-- fails (bounds check constraint)' since v1.0, but the expected output at v1.0, v1.4, v1.8 and now records the drop succeeding silently. src/2e_drop_protection.sql refuses era columns (priority 10), provenance columns and trigger (15, 16) and the range type (20), but nothing joins sql_saga.era.bounds_check_constraint, boundary_check_constraint or sync_temporal_trg_name. Probe on v1.12 (fresh database, table dp(id, v daterange, s date, e date), add_era with s/e): each of the three drops succeeds; check_integrity then reports 'named check or synchronization object is noncanonical; repair with drop_era and add_era' for each, so it is detected; with all three dropped, INSERT of v='empty', s='2024-01-01', e='2023-01-01' succeeds. The sync function (sql_saga.public_dp_p_template_sync) is refused only by dependency, so DROP FUNCTION ... CASCADE drops it with the trigger. Needs a release (installed SQL changes).
