## Goal
temporal_merge with the PL/pgSQL planner writes array columns as the native planner does

## Purpose
With sql_saga.temporal_merge.use_plpgsql_planner = on, any UPDATE of a text[] (or other array) column fails: malformed array literal

## Principle
Fix the cast in the executor's UPDATE SET; native-planner plans must stay byte-identical

## Relevant details
Situation: src/2l_temporal_merge_execute.sql builds UPDATE SET as (p.data->>'col')::type. For an array, ->> gives JSON text ['b', 'c,d'], which the array input refuses. Seen 2026-11-21 on 1.9 (pv.m in a scratch db): PL/pgSQL planner ERROR, native planner stores {b,"c,d"}. The same expression is in v1.0, so every release has it. Change: populate the value from jsonb with the column's type (jsonb_populate_record or a per-type conversion) instead of the text cast. Why: the PL/pgSQL planner is the fallback and the reference planner for tests. Cost: one generated expression, plus test cases for array, jsonb and composite columns under both planners. Question: none; acceptance below.
