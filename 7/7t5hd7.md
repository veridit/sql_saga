## Goal
temporal_merge writes every data column type exactly and identically under both planners

## Purpose
Data columns of non-scalar type are written wrong: the PL/pgSQL planner fails on arrays, composites and jsonb strings; the native default planner stores a new entity's later jsonb slices as JSON strings

## Principle
One canonical JSON payload from both planners and one typed decoder in every executor path; results identical under both planners; no change for scalar columns

## Relevant details
Shipped in v1.11 (tag on 61343fa; branch CI 44980572355 and master CI 44983601001 green on that commit). Executor (src/2l and native/src/executor_cache.rs) reads arrays, composites, json and jsonb (and domains over them) with their type through jsonb_populate_record and keeps the text cast for scalars; the native reader carries json/jsonb as themselves. Test 162 runs one scenario under both planners with identical output. Not covered: nulls nested inside a jsonb value under the PL/pgSQL planner (hug y37p3x).
