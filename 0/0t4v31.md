## Goal
PostgreSQL, and later the SQL standard, gains sql_saga's temporal model, if PostgreSQL's temporal authors want it.

## Purpose
Temporal data is hard to handle in SQL today: FOR PORTION OF covers one time slice and was reverted from PostgreSQL 19 on 15 September 2026 (lost updates under READ COMMITTED). sql_saga has a tested answer for the whole problem space (temporal_merge modes, regular-to-temporal foreign keys, coalescing); built into PostgreSQL it would help every user and remove code sql_saga maintains.

## Principle
Buy-in first: beyond research and drafts, nothing is done until Paul Jungwirth and Peter Eisentraut, who own PostgreSQL's temporal work, show interest. The owner speaks for the project; agents prepare and draft, and send nothing. Time is the main cost, so the owner may stop the epic at any decision point.

## Details
Route, smallest step first: understand the revert; open a conversation with the PostgreSQL temporal authors; then semantics and syntax; then a patch (smallest candidate: regular-to-temporal foreign key); last, ISO/IEC JTC 1/SC 32/WG 3 via Standard Norge or an existing WG3 member. History: the 1990s TSQL2/SQL-Temporal proposal failed without a vendor implementation, SQL:2011 temporal succeeded because vendors had shipped it, so implementation precedes the standard. Patch and WG3 tasks are created only after buy-in.
